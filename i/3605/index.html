Christina Cacioppo欢迎收听 Frameworks for Growth。我是 Vanta 的 CEO 兼联合创始人 Christina Cacioppo，今天与我对话的是 Replit 的 CEO 兼联合创始人 Amjad Masad。在创办 Replit 之前，你搭建了 Facebook JavaScript 基础设施的很大一部分。我们是 2018 年冬季 YC 的同期学员，而且在那之前就已经认识了。非常感谢你今天来作客。

Amjad，近二十年来你一直在思考软件开发，以及如何让它变得更简单。

眼下有哪些趋势让你特别兴奋，而我们大多数人还没意识到的？

Amjad Masad还没注意到的。我不知道大家是不是还没注意到，但我认为人们没意识到它来得有多快，software agents 的进步速度会有多快。眼下我们的 agents 第二版正在内测。从指标来看，效果大约好了五倍，而且顺便一提，第一版是九月才发布的。

简言之。是的，所以我认为就在今年，软件工程的很大一部分将被自动化。我们专注的用例尤其会获得巨大提升，因为当你试图把软件开发 agent 加进大公司代码库时，它很难产生影响力。但在 Replit 上，人们是从零开始构建应用的，所以我认为 agents 总体上会在今年开始真正见效。我们有了 reasoning models。这将是非常令人兴奋的一年。

Christina Cacioppo真不错。你们自己也在用 agents 来构建 Replit 吗？

Amjad Masad是的，有一点。我们肯定在内部使用 Replit agents。我最喜欢的一个用例是，我们有一位 HR 同事叫 Kelsey，她当时想换掉我们正在用的组织架构图软件。那些软件各有各的难用之处。

于是她决定自己做一个，三天后她就有了属于自己的工具，具备了她喜欢的全部功能。所以不仅仅是我们的软件工程团队在构建我们的软件，agents 和 Replit agents 正在让所有人都变得更高效。

问得好。大概一年前我的答案会不一样，但现在它已经完全变了。本质上，它是一种完全用自然语言构建软件的方式，你可以直接对着手机或电脑说话，它就会为你写代码。它会配置好所有的包和库，分配云数据库和存储等等，然后你可以跟它迭代。你可以改设计、加功能，就像跟人类工程师对话一样，准备好了之后直接部署，而这一切都在同一个应用里完成。我们在过去七八年里搭建了所有这些组件，我们是市场上唯一拥有全部这些组件的产品。

Christina Cacioppo你提到过去七八年一直在做这些，但如果我没记错的话，你投入在 Replit 或者类似 Replit 的想法上的时间还要更长。你在这个方向上已经工作了多久？

Amjad Masad我想第一个类似 Replit 的想法大概出现在 2008、2009 年。我当时痴迷于编程，想尝试各种不同的编程语言。我想给我的手机写代码。我有一部 Nokia Symbian 手机，那种很大的手机，我痴迷极了。我当时想，啊，我真想在上面写代码，而现在我们有了移动端的编程应用。当时做作业或学习一门新编程语言最烦人的一点，就是你必须做一大堆设置工作，一大堆 IT 杂活。你得下载一个 IDE，有时候好几个 GB 大，还得搞定各种包，更别提如果你想把程序分享给别人，它在别人的机器上几乎永远跑不起来。

那时候一切都在往云端迁移。我记得当时在用 Gmail、Google Docs，Chrome 也刚出来，而且 Chrome 真的非常强大。于是我就想，为什么我们不能在浏览器里写代码呢？我当时觉得这大概是个周末就能做完的小项目。谁能想到，20 年后的今天我还在这件事上耕耘。不过我当时确实在一个周末里做出了点东西，那是一个小型的 sandbox，你可以写很多 JavaScript 然后运行它，当时已经挺酷了。

Christina Cacioppo你大概是世界上 JavaScript 水平最高的人之一了。你是怎么开始学习 JavaScript 的？我说的不是只会写 alert 弹窗的那种，而是 Chrome 层面的，在 2008 年的 Chrome 或新版 Chrome 里能做到什么？

Amjad Masad我在约旦念完大学后，去了 Yahoo 工作。Yahoo 当时刚收购了一家叫 Maktoob 的邮件公司，那是约旦甚至可能是阿拉伯地区的第一笔大型收购。于是我去那里工作。Yahoo 是一家非常典型的、以 web 和 JavaScript 见长的公司，所以我被这门语言深深吸引，因为它有脚本语言的一面，也有函数式的一面。我当时读了很多 Paul Graham 的文章，关于编程语言和 Lisp 的那些。

这是一门非常有趣的语言，而且我觉得用它可以产生很大影响力。我还觉得这是在押注未来，而我一直在努力做到这一点——我觉得我对技术未来的走向有一种直觉。我感觉到 JavaScript 正处于一条清晰的上升轨道上：Chrome 用 V8 优化它，Gmail、Docs 这些 web 应用纷纷涌现，等等。于是我开始真正投入时间去钻研。当然，很大程度上靠的是练习。我当初做 Replit 就是为了练习编程。我觉得你只需要投入时间，如果这件事让你觉得好玩，你就会沉迷其中，一直做下去。

Christina Cacioppo我有太多问题了。你当时为什么觉得 web 会是未来？因为现在听起来理所当然，但 Gmail 当初挺奇怪的，大家并不完全愿意用；Google Docs 的普及度也很低——这些都不是注定的。

Amjad Masad我一开始用 BASIC 编程，然后是 Visual Basic。我十几岁时做了第一门生意，卖 VB6 应用。

我之前痴迷于玩《反恐精英》，所以常去网吧和朋友们在局域网联机对战。我很惊讶于这些店铺的管理需要投入这么多人工。他们雇了很多员工，你进去付一小时的网费，他们会写下你的名字，还得盯着时钟，到时间了去拍拍你的肩膀。于是我写了一套客户端-服务器管理软件，带有安全功能，限制人们只能启动游戏或打开浏览器，然后成功卖给了约旦的一批店铺。通过这一切，我深刻体会到制作和分发软件有多么痛苦，这也是 Replit 背后的故事。我从12、13岁开始做这个项目，花了两年时间，直到15岁才把它推向市场。

不，不，不，不，是15岁时用 BASIC，准确说是 Visual Basic 应用。在整个过程中，我深刻体会到分发软件有多么痛苦。所以当我看到网页、看到网络应用运转时，我心想，哦，原来这才是分发应用的方式。你不用去买光盘，不用以那种方式搬运软件。你只需打开一个网站，那就是你的应用。你可以渐进式加载，做各种事情，而且你看到所有的注意力都投向了这里，所有公司都在为此优化，我感觉这就是未来。

那么现在 AI 有什么特质，或者说其中某些东西让你有同样的感觉，因为看起来你也产生了「这就是未来」的共鸣？

是的，这其实要追溯到我还在 Code Academy 的时光。Code Academy 就是那种平台，你可以上去写一点代码，它会告诉你做得对不对，然后你进入下一道练习。它是通过动手实践来学习编程，而我当时试图给用户的代码提供反馈，为此我在手动写各种正则表达式来检查代码是否完整。我感觉自己在为代码搭建这么多工具，但大量工作都是手动的。而当时深度学习在自然语言处理方面越来越强，我就想，能不能把神经网络应用到代码上？

我当时调研了一下，已经有一些初步进展，但还不够成熟。后来在 Facebook 我也在做编译器之类的工作，一直有种冲动想去攻克这个问题。我尝试过某些技术，但那时候时机还没到。2018、2019 年我创立了 Replit 这家公司——GPT-2 发布了，我觉得，好，时机到了，我认为可以把自然语言处理应用到代码上。我们在 Replit 拥有大量的代码数据，也许可以对 GPT-2 做微调或者自己训练模型，但那还是稍微早了一点，因为工具链还不成熟。

用神经网络，尤其是 transformer 模型做任何事情都非常痛苦。所以直到 GPT-3 出现，才明显看出这些模型在代码上会表现得很好。接下来你必须去想象的下一件事，因为你其实已经可以做得很好的，是 agent。我用 GPT-3 做的最早的事情之一就是让它生成 Python 代码，然后让 Python 解释器去运行这段代码，我想我是最早这么做的人之一。后来 Langchain 出来了，他们的代码基于我的实验，基本思路就是：如果语言模型可以调用工具和外部服务，你就能看到今天我们称之为 agent 的雏形。

当然，工具调用并不是唯一需要的东西，这还不够，但如果模型能够执行无限制的一系列动作，那我认为这就是我对 agent 的定义：能够调用工具，但能执行无限制的一系列动作，直到它自然停止、得出结论。我觉得这种情况大概直到去年才真正成立。

好的。我本来想问，是具体到某个模型吗，比如 4o？

太好了。对于早期创始人，有什么真正非主流的建议吗？

硅谷有很多规矩你完全可以扔掉。当风投告诉你，这是我们的流程，我们只投这个数额，我们必须占这个比例的公司股份。这些都不是真的。他们自己总是在打破自己的规矩。这是第一点。第二，很多人告诉你应该做的事——其实有很多并不是什么好建议。我是说现在这开始成为主流了，但我大概在四五年前就不做 one-on-one 了。

对，早在这事变得酷之前。我发现 one-on-one 往往会变成一种心理治疗，而且我觉得虽然人们确实需要能找人倾诉，但这对我来说非常消耗精力。人们有很多焦虑之类的问题，我会尝试在团体环境中讨论这些，而且我们也有教练，所以我会直接把员工送去教练那里。我想聊的是工作，想了解他们对工作的担忧，诸如此类。但我不是治疗师，而且这确实会占用我的时间和精力。所以很多早期创始人发现自己总是在做心理治疗，我觉得这不是他们时间的好用途。

对于那些真正享受这种事的人，很好。但对于那些不喜欢的人。

对，关于该招谁、融资、你现在必须组建高管团队之类的观念有很多。再说一遍，你可以用很多不同的方式来运营公司。我想大概一年前我拜访过 xAI，当时他们有 70 个人，他们告诉我他们没有管理者。所有人都向 Elon 汇报，每个人都会给 Elon 发每周状态更新。

他们可能也没有 one-on-one。

他们没有 one-on-one。他大概每周或者每隔一段时间来一次，然后坐下来，有时候他会搞一场马拉松式的 one-on-one，和所有人聊，或者每个团队聊几个人。很酷的一点是，我认识那里的一位早期工程师，他现在负责 go-to-market，所以他们纯粹是工程团队。他们没有非工程师，工程师自己也做销售和市场。所以那是一种根本不同的公司运营方式。那是我们这一代最成功的创始人之一，如果不是最成功的话。所以我想说，每条规则都可以打破，但要试着把事情想清楚。显然，盲目听从所有建议是不好的。毫无理由地打破一切也是不好的，但要试着去思考，持续地 tinkering，持续地改变事物，这样你才能学到东西。

在系统中 tinkering，这个比喻很妙。

而且这很难，因为人们不喜欢变化，但他们能应付的。没关系。

好，接下来是快问快答。你最近在读什么？

老兄，我最近其实没读多少东西。

我就是一直在读这个。就是非常轻松的读物。我读了《Genius Makers》，讲的是深度学习的近期历史。我还读了不少论文、Hacker News、博客和内部文件。《Erewhon》？你听说过吗？

没有，我觉得我听说过，但没读过。

这是 19 世纪 Samuel Butler 写的。非常有趣，因为——你熟悉 The Butlerian Jihad 吗？

它来自电影《Dune》，里面有一群人不喜欢机器、反对 AI，他们发动了一场叫做 Butlerian Jihad 的运动。这个词就来自这本书。书里有一个部落或一群人，他们发现机器在某种程度上是 dysgenic 的。那时正值达尔文主义兴起，所以这是一本非常达尔文主义的书。机器让他们作为人类变得更差，或者适应性更弱，因此他们反对一切机器。所以这本书对我们这个时代非常有意思，因为我们正越来越多地用计算和 AI 来替代自身的某些部分。

是的。这很棒，我会去找来看看。你还记得你写过的第一个程序吗？

肯定是 Logo，一个 Logo 程序。Logo 是那种可以编程的 Turtle。我那时候大概六岁之类的。程序内容大概就是让乌龟左转、右转、往下走。

那有没有什么在当时看起来是天大的事，但回头看其实没什么大不了的？

去年我们裁员之后，我觉得我无法挽回公司的文化了。不知道你知不知道，裁员这件事在某种程度上会打破那种泡沫或者梦想。就好像，哦，我们并不总是……

我们不是一家人，我们并不总是在 up and to the right。会有艰难的决定。我与公司的关系并不是无条件的。我当时觉得，天哪，要挽回文化将是一项艰巨的任务，于是我开始做一些我觉得我以前从没做过的事，比如尝试搞活动之类的——虽然我们也会做一些活动，但我们当初建立文化的方式并不是靠这个。所以我做的那些事是错的。挽回文化的方式是赢，是努力工作，激励所有人，大获全胜。我们就是这么做的。而现在文化比以往任何时候都更强，实际上比以前更有趣、更令人兴奋。我们最终做了正确的事，但我当时感到的绝望是我在公司期间从未感受过的，因为我非常珍视我们的文化，而且我觉得我对它造成了持久的伤害，但事实证明并非如此。

而且你不需要去扮演一个你不是的角色来挽回它。

那反过来呢？有什么在当时看起来似乎没什么大不了的，但回头看其实相当重要的事？

早期我们在搭建 Replit 平台的时候，我们面临一个选择：是把 Replit 做得更定制化，也就是只支持一种语言或一种构建方式，还是做一个通用平台，能运行任何语言、任何包等等。我们选择了后者，当时这可能更像是一个审美上的决定，但快进到今天，LLM 登场了。那么 LLM 是用什么训练的？它们是用标准训练的。它们是用开源数据训练的，它们知道怎么使用 virtual machine，诸如此类。所以我们选择了一种更通用、更标准的平台方式，这使得你可以直接把一个 LLM 放进 Replit，它就能直接工作。而如果你看看那些 low-code、no-code 平台，它们都是定制化的。所以 LLM 并没有像影响我们一样对它们产生巨大影响。
