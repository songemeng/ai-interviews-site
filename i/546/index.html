好的，我们来聊聊 Windsurf。人们要怎样用最简单的方式理解什么是 Windsurf？是的，Windsurf 是一个 IDE，对吧？它是一个用来构建软件、开发应用的程序。说起来挺疯狂的，很多使用这个产品的人可能根本不知道什么是 IDE。这挺不可思议的，我们稍后再展开。但我们为什么要去做 Windsurf，它到底是什么？

也许我们本可以就在 Visual Studio Code 这类传统 IDE 之上做这件事。那么，稍微展开讲讲：当我们看到 AI 变得越来越强大时，我们认为人们构建技术的方式，以及对应的交互界面，将会发生显著变化。它不再会是一个传统的纯文本编辑器——用户在里面写几行代码，甚至写大部分代码，而 IDE 只提供一些基础反馈，告诉你哪里做对了、哪里做错了。这类基础反馈可能是「你的软件里有 bug」，或者「编译器报错」。

它其实可以做得更多，对吧？AI 实际上可以去修改大块的代码。我们认识到的关键一点是，在这种由 AI 驱动的新范式下，AI 很可能会写远超 90% 的软件。在这种情况下，开发者的角色，以及他们在 IDE 里做的事情，可能就变成了审查代码。也许这和过去的情况已经有所不同了。而且我们很快会在 Windsurf 上看到这一点。当我们使用这款产品时，实际上用户的很大一部分时间都在审查 AI 的输出。所以我们需要在 IDE 中构建自定义的审查流程，让这件事变得更容易完成，因为开发者不再把所有时间都花在写代码上。

这就是我们打造这款产品的根本前提。我们觉得，如果 UI 非常基础，我们会受到极大限制。举个简单的例子：我们有一款自动补全产品，可以补全几行代码。现在我们推出了一项叫 Windsurf Tab 的功能，它也会向你展示重构建议，而且这些重构几乎是内联式的。在 Windsurf 中，我们可以为此构建自定义 UI；但在 VS Code 里，由于 API 访问权限的限制，我们不得不在用户光标旁边动态生成图像，因为我们没有合适的接口来妥善展示和编辑。

底层用的是 Sonnet 对吧？我来拆解一下它最终是如何工作的：我们有一个负责规划的模型，我得说目前 Sonnet 是一个非常非常好的规划模型，OpenAI 的 GPT-4o 也很不错。但我们的做法是，尽量让基于 Anthropic 的模型或者说 Sonnet 去完成尽可能多的 high-level planning。然后我们在内部运行所有必要的模型，为 agent 提供高质量的 retrieval。

正如你看到的，agent 需要理解代码库（codebase）的其余部分到底是做什么的。我们实际上会运行模型来把整个 codebase 切分并理解它。显然，如果我们有一个一亿行代码的 codebase，把整个代码库发给 Anthropic 可不是什么好主意。首先，你根本做不到。那可是超过 15 亿个 token 的代码，对吧？所以这显然比目前最大的 context length 还要大出三四个数量级。

而且从成本和 latency 的角度考虑，你也不会想这么做。这是第一点。

你看到的第二点是，模型也能非常快速地对软件进行修改。我们构建了自定义模型，这些模型在主流开源模型之上做了 post-train，能够以极快的速度对 codebase 进行修改。之所以要这么做，一是因为速度更快，二是因为那个模型实际上能在 context 中容纳更多的 codebase 内容，因此它在应用修改方面甚至比 Anthropic 的模型还要强。

所以我觉得我们的思考方式是：我们唯一的目标是如何做出最好的产品，对吧？如何做出最好的产品，以及如何尽可能把天花板抬高。只要需要，我们就会去构建模型、训练模型。但如果我们在某个任务上做不到最好，而且我们认为开源模型更好，或者 Anthropic 更好，那我们就会直接去用开源模型或 Anthropic。那你们自己构建的模型是基于大家发布的开源模型来做的吗？是的。有意思的是，负责 retrieval 的那个模型实际上完全是我们内部 pre-train 的。

不过，对于很多不同的模块，它都是基于开源模型的。有意思的是，负责编辑和 autocomplete 的那个模型也是我们内部做的。就是在你打字的时候，我们实际上会做一些 autocomplete 相关的事情。我很乐意演示一下，不过我觉得很多用户已经熟悉这个功能了。

所以我觉得我们的思路是：我们在什么方面能做到最好，我们就会去投入训练。但如果我们做不到最好，不应该为了面子就去训练某个东西。

这可能会有点太技术化了，但你们在训练数据方面有什么有意思的吗？有的。我们从用户那里获得的一个有趣之处——这也是我们试图思考的：为什么我们能做到更好？实际上我们每小时能从用户那里获得数千万条反馈。关于他们喜欢什么、不喜欢什么，我们得到了大量反馈。对于 autocomplete 这类功能，我们获得了大量的 preference data。这些 preference data 很特别，它看起来不像你在互联网上找到的数据。
